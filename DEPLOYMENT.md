# Deployment

How to publish a new macOS UI build.

## Release Flow

1. Finish and test the UI changes locally.
2. Update `pyproject.toml` version (both `[project].version` and
   `[tool.briefcase].version` — they must match).
3. Update `CHANGELOG.md`.
4. **Reconcile `Third party notices.txt`** with what is actually shipped:

   ```bash
   bash scripts/list_bundle_packages.sh
   ```

   Every package in that output must appear in `Third party notices.txt`,
   with the right version and license. New transitive dependencies sneak in
   from bumps and must be added here before release.
5. Push a version tag.
6. Check the GitHub Release created by the workflow.

## Local Preflight

Before tagging, build the local DMG once:

```bash
bash scripts/build_dmg.sh
```

Check that the artifact exists (the filename embeds the current version):

```bash
ls -1 dist/*.dmg
# dist/PDF-MD Anonymizer-0.1.0.dmg
```

Mount the DMG and verify it contains:

- `PDF-MD Anonymizer.app`
- `Applications` (symlink)
- `First Launch.txt`
- `Third party notices.txt`

Run the app from the DMG once before publishing if the UI changed. The first
launch needs the Gatekeeper workaround described in `First Launch.txt`.

## Tag Release

The workflow at `.github/workflows/release.yml` builds a macOS DMG and attaches
it to a GitHub Release when a version tag is pushed.

Use a `v*` tag matching `pyproject.toml`:

```bash
git tag v0.1.0
git push origin v0.1.0
```

After the workflow completes, open the GitHub Release and confirm the DMG is
attached. The release body is autogenerated from commits since the previous
tag.

## Signing and Notarization

Current state:

- The app is ad-hoc signed during local and CI packaging
  (`codesign --force --deep --sign -`).
- The app is not notarized.
- macOS blocks first launch for users.

User workaround is documented in `First Launch.txt`.

Third-party dependency notices are in `Third party notices.txt`.

For a polished public release later, add:

- Apple Developer ID signing.
- Notarization with Apple.
- Stapling the notarization ticket to `PDF-MD Anonymizer.app` or the DMG.

## Troubleshooting

**numpy codesign race.** If `briefcase package` fails with
`resource fork, Finder information, or similar detritus`, the numpy `.cstemp`
files were not cleaned up. Re-run `scripts/build_dmg.sh` — it strips the
ad-hoc signatures before re-packaging.

**Stale bundle after a dependency bump.** Delete the cached scaffold and
rebuild from scratch:

```bash
rm -rf ~/.briefcase-out/pdf-md-anonymizer/build
bash scripts/build_dmg.sh
```
